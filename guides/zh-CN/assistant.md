# 个人助理

> 🧑‍💼 **本章内容** — 开启并使用 Fello 的内置个人助理：创建助理、配置来源模型与 MCP、记录提醒、沉淀记忆，以及把长任务交给后台 Worker。

个人助理是常驻在 Fello 里的私人助手。和项目会话不同，它不属于任何项目，也不需要你每次从头交代背景：它有自己的工作区、长期记忆和日记，可以主动提醒你，也能把耗时的任务交给后台子代理。

---

## 开始之前

个人助理需要一个**已启用的 API Agent** 作为「来源模型」。它不支持 Stdio Agent。

1. 打开 **设置 → Agents**，确认已经添加并启用一个 OpenAI 兼容的 API Agent（例如 DeepSeek、Kimi、OpenAI 等）。
2. 打开 **设置 → 个人助理**，打开 **启用个人助理** 开关。
3. 回到侧边栏，在「个人助理」分区点击右侧的 **新增** 按钮。
4. 填写名称，选择来源 Agent 和需要启用的 MCP Server，点击 **创建**。

创建后会直接进入助理页面。侧边栏里每个助理是一行，固定在项目列表上方；关闭全局开关后整个分区会隐藏。

> 💡 可以创建多个助理，例如「工作助手」「写作助手」。它们各自拥有独立的对话、记忆、提醒和 Worker，但共享设置页里的 Worker 类型。

---

## 页面导览

助理页面和会话页面结构相似，分为三块：

| 区域 | 用途 |
|------|------|
| 中间聊天列 | 和助理对话、查看工具调用、回答 Ask User 提问 |
| 右侧面板 | **日历**（提醒与日记）、**文件**（助理工作区）、**Worker**（后台子代理） |
| 详情列（按需出现） | 打开文件、日记、记忆或某个 Worker 的只读对话 |

页面顶部显示：

- 左侧：助理名称和当前状态（Ready / Connecting / Dreaming…）。
- 右侧：朗读按钮、上下文用量按钮、**助理配置**（齿轮）和面板开关。

聊天输入框右下角可以切换**模型**和**思考等级**。思考等级为 `Auto` 时使用模型默认行为；`Max` / `High` / `Low` 会映射为对应的推理强度。

> 💡 助理输入框目前只接收文本，不支持添加附件。需要处理文件时，直接把文件路径告诉它，或把文件放进助理工作区后让它读取。

## 配置助理

点击聊天列右上角的 **齿轮** 打开助理配置：

| 配置 | 说明 | 何时生效 |
|------|------|----------|
| 助理 ID / Workspace | 用于定位数据和文件，可直接打开文件夹 | — |
| 来源 Agent | 助理使用的 API Agent | 点击「重启助理」后 |
| MCP 服务器 | 助理可调用的外部工具 | 点击「重启助理」后 |
| Dream → Max tokens | 上下文超过多少 token 时必须沉淀记忆 | 点击「重启助理」后 |
| Dream → Preferred time | 每天几点执行记忆沉淀 | 点击「重启助理」后 |

名称和启用 / 停用不在这里：在侧边栏右键助理即可重命名或停用，立即生效。

> ⚠️ 修改来源 Agent、MCP 或 Dream 配置后，必须点击底部的 **重启助理**。只改界面不会写入配置文件。

## 日常对话

- **直接说需求**：助理可以规划、写作、分析、查资料、读写文件。它知道自己的 workspace 路径，并会默认把相对路径解析到那里。
- **让它读文件**：可以直接给绝对路径，也可以把文件放到助理工作区。助理能读取本机任意位置的文件，但写入助理自己的运行时目录会被拒绝。
- **写入工作区外**：助理被要求先征得你的同意。它可能通过 Ask User 弹窗询问，确认后才会写。
- **删除文件**：只能删除助理工作区内的文件。桌面端会进系统废纸篓，可在系统里恢复；无头服务器上是永久删除。
- **分享产物**：让助理把结果写成文件，然后用 `share_to_user` 发给你。产物会出现在右侧 **文件** 面板，也可以点开预览。
- **定时提醒**：直接说「明天下午 3 点提醒我交周报」「每个工作日早上 9 点提醒我看邮件」。提醒会以消息形式出现在对话里，到点还会弹系统通知。
- **查过去的事**：问「上周我们聊过什么」「我之前说过的项目代号是什么」，助理会检索日记来回答。

> 💡 助理会把提醒当作应用注入的事件，而不是你的新消息。如果某条提醒因为助理正忙而延迟投递，它会标记为重试，只提醒一次。

## 日历、日记与记忆

右侧 **日历** 标签页按天展示：

- **提醒**：每个触发时间一张卡片，显示倒计时、已触发或已错过；当前时刻有一条 `Now` 分隔线。
- **日记**：当天覆盖到的日记条目。点击可在详情列阅读全文。

**记忆** 不在日历里，而是通过上下文用量按钮打开：

- 点击输入框上方的 **用量按钮** → **查看记忆**，可以看到 Dream 维护的 `memory.md`。
- 同一菜单里的 **立即沉淀** 可以手动触发一次记忆沉淀。

---

## 记忆沉淀（Dream）

Dream 是助理整理上下文的方式：它把当前对话压缩成一篇日记，并更新长期记忆，然后清空模型可见的对话历史。界面上的聊天记录不会消失。

### 什么时候执行

- **上下文超限**：当历史 + 系统提示词达到 `Max tokens`（默认 96,000）时，本轮结束后立即执行；下一次提问前如果还没完成，会先等它完成。
- **每天定时**：当新对话累计到约 8,000 token 后，在 `Preferred time`（默认凌晨 2:00）执行。
- **手动**：打开用量菜单 → **立即沉淀**，确认后执行。

手动触发只要求「已连接、当前空闲、有模型、有历史」，不要求达到 token 门槛。

### 执行时会发生什么

1. 助理回顾这段对话，生成当天的日记（摘要、时间线、事实、决定、承诺、偏好、未解决问题）。
2. 重写长期记忆（事实、偏好、待办承诺、进行中的项目）。
3. 日记写入 `memory/diary/`，记忆写入 `memory/memory.md`。
4. 清空模型历史，之后的对话从这份记忆继续。

> ⚠️ 记忆沉淀会清空模型可见的历史。虽然界面上的聊天记录还在，但助理不会再逐字回看旧对话，只会依赖记忆和日记。重要信息请在触发前确认已经说清楚。

### 失败了怎么办

如果模型返回的结构不符合要求，聊天头部下方会出现一条可关闭的错误提示。关闭后后端也会清掉这条状态，离开页面再回来不会重复出现。失败不会在同一次目标上循环重试：定时任务会等下一个计划时间；如果上下文仍然超限，下一轮结束后会再次尝试。

## Worker（后台子代理）

Worker 是助理可以调用的后台 ACP 智能体。适合「读很多文件」「写长文档」「跑一段较久的研究或代码任务」这类工作。助理在对话里会自己判断是否委派；你也可以直接说「这个任务交给 Worker 做」。

### 先配置 Worker 类型

打开 **设置 → 个人助理 → Worker 类型**，点击 **新增 Worker 类型**：

| 字段 | 说明 |
|------|------|
| 名称 | 展示名，例如 `Coder`、`Researcher` |
| 描述 | 告诉助理什么时候该用这个类型 |
| Agent | 该 Worker 使用的 Agent（Stdio / API 均可） |
| 模型 | 留空使用 Agent 默认模型 |
| 权限 | `Ask`：遇到工具调用询问助理；`Allow all`：自动允许 |
| Instructions | 追加到每次 Worker 任务的角色说明 |
| Features / MCP | 该 Worker 可用的 Fello 功能与 MCP Server |

所有助理共享这些类型。只有在「启用 + 已选择 Agent + Agent 未停用」时，助理才能看到并创建该类型；一个可用类型都没有时，助理不会获得 Worker 工具，只能自己做。

> 💡 已有 Worker 会保留创建时的类型快照。之后修改或删除类型，不会影响已经创建的 Worker。

### 使用 Worker

在聊天里直接描述任务即可，例如：

- 「把这个目录的会议记录整理成一份周报，放到 workspace 的 reports 下。」
- 「让 Coder 修一下这个脚本的 bug，修完告诉我改了哪些文件。」
- 「研究一下这几个链接，写一份对比文档。」

助理会：

1. 选择一个匹配的 Worker 类型，创建一个后台会话。
2. 把完整任务一次性交给它（Worker 看不到你们的聊天，所以任务必须是自包含的）。
3. 立即回到对话；Worker 在后台跑。
4. 完成或失败后，助理会收到事件并在聊天里向你汇报。
5. 需要权限时，助理会收到权限事件；无害操作它自己决定，可能影响工作区外文件或命令时会先问你。

右侧 **Worker** 标签页能看到所有 Worker 的状态、类型、Agent / 模型、workspace 和轮数。点击 **View chat** 可以只读查看它的完整对话；在桌面端点击 Worker 文件夹或路径可以在访达中定位。

Worker 跑完后可以关闭或终止：

- **关闭（worker_close）**：释放进程，保留记录和对话；下次再发任务会重新连接。
- **终止（worker_terminate）**：删除 Worker 记录和对话，**不会删除它工作区里的文件**。如果这些文件在助理工作区内，可以让助理用 `fs_delete` 清理；在工作区外需要你自己删除。

> ⚠️ 应用正常退出会取消运行中的 Worker；异常崩溃后，下次启动会把它们标记为 `interrupted`，不会自动继续。让助理检查状态后再决定是否接着跑。

## 数据与隐私

每个助理的数据都在本机：

```text
~/.fello/assistants/<assistant_id>/
├── config.json
├── session/          # 模型状态与历史
├── chat/             # 界面聊天记录
├── memory/           # 记忆与日记
├── reminders/        # 提醒
└── workers/          # Worker 记录与对话
```

助理的工作区在：

```text
~/.fello/workspaces/__assistant__<assistant_id>__/
```

可以在助理配置里打开「Assistant Folder」或「Workspace Folder」。

- 助理**不会**修改自己的运行时数据（`session/`、`chat/`、`memory/`、`workers/`、`reminders/`）。
- 删除助理会同时删除它的数据目录和工作区，且不可恢复。
- 助理可以使用你勾选的 MCP Server；MCP 的凭据仍保存在全局设置里。
- 助理的思考与回复会发送给你选择的 API 服务商，是否上传取决于该服务商的隐私政策。

## 常见问题

**新增助理按钮点了直接跳到 Agents 设置页？**  
说明还没有可用的 API Agent。先在设置 → Agents 添加并启用一个 OpenAI 兼容的 API Agent。

**助理一直显示 Unavailable / 配置错误？**  
检查来源 Agent 是否被停用、API Key / Base URL 是否正确；修改后在助理配置里点 **重启助理**。

**修改了 MCP，但助理还用不了？**  
MCP 改动需要点 **重启助理** 才生效。

**为什么助理不记得刚才聊的内容？**  
可能刚执行过记忆沉淀。它现在依赖 `memory.md` 和日记；可以打开「查看记忆」确认内容。也可以在记忆里补充遗漏的事实。

**为什么助理把任务交给了 Worker，而不是自己做完？**  
长任务、需要读很多文件或写长文档时，委派更稳。你可以直接说「不要用 Worker，你自己做」，也可以调整 Worker 类型的描述来影响它的选择。

**Worker 显示 Interrupted？**  
上次 Fello 退出时它还在运行。让助理查看状态，或直接让助理继续该 Worker；它会重连并接着跑。

**提醒没有弹出来？**  
检查助理是否启用、Fello 是否在运行。一次性提醒在应用关闭期间错过不会补发；周期提醒会在下一个触发时间继续。
