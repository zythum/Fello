# 权限控制与安全

> 🛡️ **Fello 的权限系统**让你完全掌控 AI Agent 的行为。每当 Agent 需要执行敏感操作（写文件、运行命令等），都会请求你的许可。

## 权限模式

Fello 提供两种权限模式，在创建会话时选择：

- 🔒 **Ask 模式（默认）** — 每次 Agent 请求敏感操作时弹窗询问，你逐一审批。适合需要严格控制的场景。
- ⚡ **Allow All 模式** — 自动批准所有权限请求，Agent 可自由执行操作。适合信任的 Agent 和快速迭代场景。

---

## 权限请求流程

在 Ask 模式下，当 Agent 需要执行敏感操作时，Fello 会**强制中断执行流程**，弹出权限确认对话框：

1. Agent 发起权限请求（如：写入文件、执行命令）
2. Fello 弹出 **Permission Required** 对话框
3. 对话框显示操作详情和可选策略
4. 你选择允许或拒绝

> 🔒 **安全保障：**
> - **阻断式设计** — Agent 在收到你的回复前会完全暂停，不会绕过权限检查继续执行
> - **操作透明** — 弹窗中展示完整的工具名称、操作类型和参数详情，你可以清楚看到 Agent 要做什么
> - **三种选择** — 「允许一次」仅放行本次操作；「始终允许」记住该类操作的授权；「拒绝」阻止执行并通知 Agent
> - **按类别管理** — 权限以工具类型（如 write_file、shell_exec）为粒度，而非单个文件。始终允许"写文件"意味着允许写入任意文件

---

## "始终允许"记忆

对于你信任的操作类型，可以勾选 **Always Allow**（始终允许）：

- 勾选后，同类操作将自动批准，不再弹窗
- 记忆持久化到会话状态中，重启后仍然有效
- 仅对当前会话生效，不影响其他会话

> 💡 **示例：** 如果你始终允许了"写入文件"权限，后续 Agent 写入任何文件都不会再弹窗。但"执行命令"仍然会单独询问。

---

## 权限请求队列

当 Agent 连续发起多个权限请求时，Fello 会将它们排入队列，逐个展示给你处理。你不会错过任何一个权限请求。

## 数据安全

| 安全措施 | 说明 |
|---------|------|
| 本地数据存储 | 所有数据存储在本地 `~/.fello/` 目录，不上传到云端 |
| 进程隔离 | 渲染进程无 Node 直连能力，系统操作均通过受限 IPC 进入主进程 |
| API Key 本地存储 | API 密钥仅存储在本地配置文件中 |
| WebUI Token 验证 | 远程访问需要 Token 认证 |

### WebUI Token 认证机制

| 机制 | 说明 |
|------|------|
| **首次访问** | 必须在 URL 中携带 `?token=xxx` 参数，Token 正确后服务端设置 Session Cookie |
| **后续请求** | 通过 Cookie（`fello_token`）自动认证，无需每次携带 Token |
| **Cookie 生命周期** | Session Cookie（无 Max-Age），关闭浏览器后失效，需重新用 Token URL 访问 |

> ⚠️ **安全建议：**
> - **使用强 Token** — 启动 WebUI 时设置高强度的 Token 字符串，避免使用简单密码
> - **注意网络环境** — WebUI 默认监听局域网。若暴露在公网，Token 即等同于完整的系统访问权限
> - **不使用时关闭** — WebUI 服务不需要时应及时关闭，减少攻击面
> - **Token 即权限** — 知道 Token 的人可以完全控制 Fello（含文件操作、终端执行），请勿泄露给不信任的人

---

## 最佳实践

> ✅ **推荐做法：**
> - 对不熟悉的 Agent 使用 Ask 模式，观察其行为后再决定是否放宽
> - 对信任的本地 Agent（如 kiro-cli）可使用 Allow All 模式提高效率
> - 定期检查"始终允许"列表，移除不再需要的权限
> - WebUI 使用强 Token，不使用时关闭服务
> - 敏感项目建议使用独立会话，避免权限记忆交叉
